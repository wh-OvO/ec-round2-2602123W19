## 第 0 步（门禁）新板子的 PWM 到底有没有从新脚出来

**这是换板后最大的风险，也是唯一"四路全灭"级别的风险。**

野火板上 `PA0~PA3` 是 KEY1 + 三颗 RGB 灯。而我们**只把引脚挪走了，定时器参数一个没改**——
靠的是 `main.c` 里手工写的那两行：

```c
__HAL_AFIO_REMAP_SWJ_NOJTAG();    /* 关 JTAG，留 SWD —— PA15/PB3 出厂是 JTDI/JTDO */
__HAL_AFIO_REMAP_TIM2_ENABLE();   /* TIM2_REMAP = 11：全重映射 */
```

CubeMX **不会**生成这两行。漏了会怎样：引脚 AF 配置是对的、代码一行没错，
但信号仍然从 `PA0~PA3` 出来 → **四路舵机一动不动**。

### 判据一：代码层（10 秒）

```powershell
cd C:\Users\Lenovo\Desktop\elec_control\rm_arm
Select-String -Path Core\Src\main.c -Pattern 'REMAP_TIM2|REMAP_SWJ'
```

必须**两行都命中**。一条都没有就是没加。

### 判据二：硬件层（万用表，不用示波器）

PWM 是 50Hz、幅值 3.3V。**万用表直流档读的是平均值**：

```
读数 ≈ 3.3V × 脉宽 / 20000µs
```

| 发的脉宽（`0x31`） | 理论读数 |
|---|---|
| 500 µs | **0.08 V** |
| 1000 µs | 0.17 V |
| 1500 µs | **0.25 V** |
| 2000 µs | 0.33 V |
| 2500 µs | **0.41 V** |

**操作**：表笔接 `PB11`（J4）与 `GND`，在 ArmHost「调试」页的单路伺服控件里把脉宽从 500 扫到 2500。

**三种读法的含义**（这一步的价值就在这张表）：

| 读数 | 说明 |
|---|---|
| 随脉宽**单调变化** | ✅ 正常，`REMAP` 生效 + 通道使能 + CCR 换算都对 |
| **恒 0 V** | `REMAP` 没生效（还在 PA3）、或通道没使能、或引脚被别的复用占了 |
| **恒 3.3 V** | 引脚配成了普通 GPIO 输出高（不是 AF 模式） |

> **为什么用平均值而不去找示波器**：50Hz 的周期是 20ms，占空比 2.5%~12.5%，
> 任何数字万用表的 DC 档都会把它平均掉。这个方法同时验证了"频率是 50Hz"——
> 如果频率错了（比如 1kHz），同样的脉宽平均值会差 20 倍，读数对不上表。

**只接一个舵机**（建议 J4 / `PB11`），先过这一关再谈别的。

## 第 2 步 T2 三档 profile：判据是**形状**，不是数字

**同一帧、只改最后 1 字节**（`profile`），这样三个结果的差异只可能来自曲线本身。

ArmHost 控制页有「运动时长」和「速度曲线（阶跃/梯形/S 曲线）」两个输入，
所以不用手拼帧。**固定** J4：`10° → 50°`，时长 `2000 ms`，只换曲线。

### 三种形状长什么样

| profile | 位置曲线 | **角速度曲线（关键）** |
|---|---|---|
| **0 阶跃** | 一步竖跳，瞬间到 50° | 一根**极窄的竖线**，其余时间是 0 |
| **1 梯形** | 抛物线 → 斜直线 → 抛物线 | **梯形**：斜上 → **长平顶** → 斜下 |
| **2 S 曲线** | 平滑 S，全程都在弯 | **钟形**：从 0 平滑升起、中点最高、平滑落回 0，**没有平顶** |

### 三条一眼判据

1. **阶跃 vs 其它**：有没有斜坡。有斜坡就不是阶跃。
2. **梯形 vs S**：**角速度有没有长平顶**。
   梯形约 `1600 − 400 = 1200ms` 是**水平直线**；S 曲线只有一个峰点，两侧都在变。
3. **峰值比 1.5 倍**：同样时长、同样行程，`S 峰值 ÷ 梯形峰值 = 1.875 ÷ 1.25 = 1.5`。
   这个数字对不上，说明 `ARM_TRAP_ACC_RATIO` 或五次多项式系数写错了。

## 第 3 步 期望值：自己算一遍再对表

**三个公式（背下来，答辩会问）**

```
平均速度      v̄ = D / T
梯形峰值      Vp = v̄ / (1 − r)        r = ARM_TRAP_ACC_RATIO = 0.2  →  1.25 v̄
S 曲线峰值    Vp = 1.875 v̄
加速段时长    Ta = r · T               = 0.2 T
```

> **梯形比线性慢？错。**
> 为了把加减速段少走的距离补回来，匀速段的速度**必须比平均速度高**（高 25%）。
> 同样时长下，梯形中段比匀速更快。

**按上面的测试帧算（D = 40°，T = 2000ms，v̄ = 20°/s）**

| 时刻 | 0 阶跃 | 1 梯形 | 2 S 曲线 |
|---|---|---|---|
| 峰值角速度 | — | **25 °/s**（平顶 400~1600ms） | **37.5 °/s**（只在 1000ms 一点） |
| 加速段 | 无 | 0~400ms | 无（全程都在变） |
| `t = 400ms` 位置 | 50°（已到位） | **15°** | **12.3°** |
| `t = 1000ms` 位置 | 50° | **30°** | **30°** |
| `t = 1600ms` 位置 | 50° | **45°** | **47.7°** |
| `t = 2000ms` 位置 | 50° | 50° | 50° |

<details>
<summary>这几个位置是怎么算出来的（点开看推导）</summary>

**梯形**（`r = 0.2`，`k = 2r(1−r) = 0.32`）：

- 加速段 `τ < r`：`s = τ² / k`
- 匀速段：`s = (τ − r/2) / (1 − r)`
- 减速段：关于 `τ = 0.5` 对称，`s = 1 − s(1−τ)`

`τ = 0.2` 时 `s = 0.04 / 0.32 = 0.125` → `10 + 40×0.125 = 15°` ✅
`τ = 0.5` 时 `s = (0.5 − 0.1)/0.8 = 0.5` → `30°` ✅

**S 曲线**：`s = 6τ⁵ − 15τ⁴ + 10τ³`（五次多项式 smootherstep）

`τ = 0.2`：`6(0.00032) − 15(0.0016) + 10(0.008) = 0.05792` → `10 + 2.32 = 12.3°`
`τ = 0.8`：`6(0.32768) − 15(0.4096) + 10(0.512) = 0.94208` → `10 + 37.68 = 47.7°`

</details>

> ⚠️ **回归警告（`plan.md §6.4` 也写了）**：以前测 T2 用的帧 `profile` 都是 `00`，
> 那时被当成线性跑。**现在 `00` = 阶跃，会瞬跳**。这是终于按协议执行，不是 bug。
> 要测插补，必须把曲线选成梯形或 S。

## 第 4 步 200Hz：能验什么、**不能**验什么（重要）

### 结论先说：200Hz 在这套硬件上**观测不到**

理由很硬，值得理解：

```
PWM 周期      = 20 ms（50Hz，舵机决定的，不能改）
插补周期      = 5 ms（200Hz）
```

一个 PWM 周期里，`CCR` 会被改写 **4 次**，但舵机只在**周期开始的那一次更新事件**取值。
后写的 3 次中间值全部被覆盖。

- 插补 50Hz：每个周期写 1 次，写的就是本周期该到的位置。
- 插补 200Hz：每周期写 4 次，只有最后 1 次生效——而它的值和 50Hz 那次**几乎相同**。

所以**无论 50Hz 还是 200Hz，PWM 波形和上位机曲线完全一样**。
别花时间在示波器或角速度图上"找" 200Hz，找不到的。

### 那这条判据怎么过？三条真实证据

1. **代码层（评审最可能用的方式，也是 G5 答辩会问的）**

   | 该看什么 | 在哪 |
   |---|---|
   | `ARM_INTERP_TICK_MS == 5u` | `Core/Inc/arm_cfg.h:200` |
   | 插补和上报是**两个独立 `if`** | `proto_app.c:1081` 与 `:1092` |
   | 编译期守卫：`APP_REPORT_MS ≥ 插补`、且能整除 | `proto_app.c:58`、`:61` |
   | `interp_tick()` 里**不出帧** | `proto_app.c:1085` 注释 |

   要能指着代码说：**"5ms 一拍算目标，20ms 一帧报状态，两者解耦。"**

2. **"没有丢拍"的间接证据**

   时间驱动实现下（`s = f(t/dur)`），插补慢一点总时长照样对，所以**时长测不出频率**。
   但**丢拍会破坏角速度曲线的平滑度**——某拍被 I²C 超时拖到 12ms，舵机就会在
   12ms 内保持旧脉宽，曲线上留一个台阶。

   **判据**：梯形规划下角速度应该是**笔直的斜线 + 绝对平的水平线**。
   如果平顶上有规律的小台阶，就是 5ms 节拍被拖了（去查 AS5600 / MPU6050 的读取耗时）。

3. **答辩口述：200Hz 的意义是什么**

   不是为了"让舵机走得更细"（舵机受 50Hz PWM 限制，细不了），而是：
   - 每拍算出的**角度增量本身连续**（任务书原话"相邻两拍角度增量连续，不允许阶跃"）
   - **底座闭环的控制频率提高到 4 倍** → 跟踪滞后变小
   - 为以后换更快的执行器留余量

> 如果一定要一个数字：可以在 `proto_app.c` 里加个只增计数器，每秒往 USART1 打一行
> `interp/s = 200`。现在板载 CH340 直连，**看得见**。这需要改代码，要做就说一声。

## 第 6 步 T3 三条还没验的（§6.3 末尾留的）

| # | 项目 | 怎么验 | 期望 |
|---|---|---|---|
| 1 | 上电自动回零 | 拔电重上电，盯 ArmHost 状态 | 0.5s 后 `bit1 回零中` 亮，走完熄灭，模式回**手动** |
| 2 | 回零位 | 同上 | `bit1` 期间不为 0 |
| 3 | 回零途中被取消 | 上电后 **0.3s 内**发一个 `0x20` | **不执行**自动回零，按新目标走 |

> ⚠️ **有一个必须提前知道的物理事实**：`arm_init()`（`arm_pwm.c:72`）在上电那一刻
> 就把四路写成 `deg_home`。所以舵机一开始就"瞬跳"到零位，**之后 500ms 的自动回零
> 是空转（位移恒为 0）**，"平滑回零"在舵机上看不到，只能看 `bit1`。
>
> 这不是 bug，是位置舵机的物理限制：舵机上电后只要收到 1500µs 就会往中位跑，
> 想让"上电即零位"变成"缓缓走回零位"在开环位置舵机上做不到。
> **答辩被问就这样答**，并且强调：真正的 T3 保护是"输出永远不超出标定区间"。
