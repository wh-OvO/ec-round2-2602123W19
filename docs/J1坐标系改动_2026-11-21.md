## 一句话

上位机 `−180…+180` **平移 180°** 映射到固件 `0…315`，`home = 0`，`限位 = 315`，**不缩放**。

```
真实角（从 home 量） = 上位机角 + 180
```

| 上位机 | 固件 | 真实角 | 现象 |
|---|---|---|---|
| −180 | 0 | 0 | 停在 home 柱 |
| −90 | 90 | 90 | |
| 0 | 180 | 180 | 行程中点 |
| +90 | 270 | 270 | |
| **+135** | **315** | **315** | 撞点，到头 |
| +136…+180 | 被钳在 315 | 315 | 到头了，不动 |

## 改动点 1／4 —— `Core/Src/arm_cfg.c`（J1 的限位）

在 `g_arm_joint[]` 的 J1 那一项里（约 105 行，`0xED` 上方那个 struct）：

```c
/* 改前 */
    .deg_min        = 2,
    .deg_max        = 312,      /* ← 撞点 315，内退 3° 留过冲余量 */
    .deg_home       = 2,        /* 软限位内侧，离接缝 25°。**不是行程中点** */

/* 改后 */
    .deg_min        = 0,
    .deg_max        = 315,
    .deg_home       = 0,
```

- `2 → 0`：home 柱就是 0，上位机的 −180 才名副其实。
- `312 → 315`：你实测「离整圈还差 45°」，315 就是撞点，直接拿来当限位。
- `deg_home = 0`：上电默认目标。

> ⚠️ 只动 J1。J2/J3/J4 是位置舵机，坐标系是 0~180，一起改会全部撞限位。

## 改动点 2／4 —— `Core/Inc/arm_cfg.h`（编码器零点）

约 368 行：

```c
/* 改前 */
#define ARM_BASE_ENC_ZERO_DEG    11.2f

/* 改后 */
#define ARM_BASE_ENC_ZERO_DEG    8.6f
```

**为什么必须跟着改**：home 柱在旧坐标里读 **3.1**（由第一张图 上位机 −153.9 + 老 CENTER 157 反推）。
限位从 2 挪到 0、CENTER 从 157 挪到 157.5 之后，柱子会落在 **3.6** —— 那样命令 −180（固件 0）时
PID 会一直推着柱子磨。改成 8.6 让柱子落在新坐标的 **1.0°**：误差 1° < 死区 1.5° → 输出 0，不磨。

推导（`机械角 = wrap180(SIGN × (raw − ZERO)) + CENTER`，`SIGN = −1`）：

```
① 老参数反推柱子原始读数：  3.1 − 157 = −(raw − 11.2)      ⇒ raw_home = 165.1
② 新参数要求柱子读 1.0：    −(165.1 − ZERO) = 1.0 − 157.5  ⇒ ZERO = 8.6
```

以后谁再动 `deg_min/deg_max`（CENTER 跟着变），ZERO 要按这两步重算。

## 改动点 3／4 —— `Core/Src/proto_app.c`（上位机映射）

约 199 行，**整块替换**。这是 HEAD 里原来的样子：

```c
/* 改前（HEAD） */
static int32_t j1_center_x10(void)
{
  const int32_t lo = (int32_t)g_arm_joint[0].deg_min;
  const int32_t hi = (int32_t)g_arm_joint[0].deg_max;
  return ((lo + hi) * 10) / 2;
}

static int32_t j1_to_fw_x10(uint8_t j, int32_t q)
{
  return (j == 0u) ? (q + j1_center_x10()) : q;
}

static int16_t j1_to_host_x10(uint8_t j, int16_t q)
{
  if ((j != 0u) || (q < 0)) { return q; }
  return (int16_t)((int32_t)q - j1_center_x10());
}
```

```c
/* 改后 */
#define J1_HOST_OFFSET_X10   1800     /* 180.0°，单位 0.1° */
#define J1_SENTINEL_X10      (-500)   /* −50°，区分故障哨兵 */

static int32_t j1_to_fw_x10(uint8_t j, int32_t q)
{
  return (j == 0u) ? (q + J1_HOST_OFFSET_X10) : q;
}

static int16_t j1_to_host_x10(uint8_t j, int16_t q)
{
  if ((j != 0u) || ((int32_t)q < J1_SENTINEL_X10)) { return q; }
  return (int16_t)((int32_t)q - J1_HOST_OFFSET_X10);
}
```

两处要注意：

- `j1_center_x10()` 删掉了 —— 新映射固定用 180°，不再跟 `deg_min/deg_max` 联动。
  （**代价**：以后改限位，上位机的 −180 不再自动跟着走。要联动就得把 180 换成别的规则。）
- 哨兵判据从 `q < 0` 改成 `q < −50°`。新坐标下正常读数可以到 0 甚至 −0.5，
  老的 `q < 0` 会把它们误判成「传感器坏了」（−100° / −200°）。

## 改动点 4／4 —— `Core/Src/arm_joint.c`（误差不再绕 ±180）

`vel_tick()` 里，约 210 行：

```c
/* 改前 */
  err        = wrap180(s_tgt_deg[joint] - meas);
  s_base_err = (err >= 0.0f) ? err : -err;

/* 改后 */
  {
    float m = meas;
    if (m < (float)c->deg_min) { m = (float)c->deg_min; }
    if (m > (float)c->deg_max) { m = (float)c->deg_max; }
    err = s_tgt_deg[joint] - m;
  }
  s_base_err = (err >= 0.0f) ? err : -err;
```

**理由**：底座的行程是一条 **弧**（0 → 315），不是圆环。圆环才需要 wrap。
旧代码在「臂停在 315、命令回 0」时会算出 `wrap180(0 − 315) = +45` → **判成往前走** → 一头顶进柱子；
新代码算 `−315` → 往回走（唯一走得通的方向）。

这条和坐标系是**两件事**，可以单独保留/单独回滚。
