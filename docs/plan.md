## 1. 三条铁律

### 铁律 1：动手前先读本文件的 §2（谁负责什么）和 §6（未提交改动）

```powershell
# 30 秒确认有没有别人的未提交改动
cd C:\Users\Lenovo\Desktop\elec_control\rm_arm
git status --short
git log --oneline -5
```

`git status` 里出现你**不认识**的 `M` 文件 → 先读 §6，那可能是别的会话正在做的活儿。
看不懂就先问用户，**不要直接覆盖**。

### 铁律 2：git 操作只碰自己的文件

| 允许 | 禁止 | 为什么 |
|---|---|---|
| `git add Core/Src/我改的那个.c` | `git add -A` / `git add .` | 会把别人未完成的半成品一起提交 |
| `git commit -m "..."` | `git reset --hard` | 直接抹掉别人的工作 |
| `git diff <文件>` | `git checkout -- <文件>` | **用户的源码里有手写标注，见铁律 3** |
| `git stash`（先确认没别人的东西） | `git commit --amend` / `git rebase` | 改写已有的提交历史 |

### 铁律 3：这四个文件里有**用户手写的学习标注**，永久禁止整文件覆盖

用户在自学 STM32，在源码里加了自己的注释，这些**丢了就找不回来**：

| 文件 | 标注长什么样 |
|---|---|
| `Core/Inc/arm_cfg.h` | `#菜单的意思#`、`#时钟#`、`#标准整数类型#` |
| `Core/Src/arm_pwm.c` | `#语法糖标签#`、`/* #72MHz / (PSC + 1) = 2MHz ... # */` |
| `Core/Src/main.c` | `//6个函数声明`、`//保证是C 编译器编译...`、`//头文件外部链接` |
| `Core/Inc/arm_pwm.h` | 同上 |

**只允许用 `edit` 做局部字符串替换；禁止 `write` 整文件重写，禁止 `git checkout`。**

### 铁律 4：**`plan.md` 同时被多个会话写，是正常的**

这份文件是**共享板**，不是任何会话独占的。你读它、改它的那几分钟里，别的会话很可能也在改同一段。

- **发现"刚刚被人改过"是正常现象**，不是冲突 —— 先看它新增了什么，再动你自己的
- 用 `edit` 做**局部替换**，**禁止 `write` 整文件重写**（会把别人这一轮新增的整段抹掉）
- 标题行的「最后更新」如果已被别人改过，**保留他写的内容、在后面追加你的**，不要整行替换
- 两个会话改到同一段、`edit` 报 `old_string was not found` → **重新读一遍再改**，不要绕过、不要放弃
- 会话之间**不打招呼就动别人的段落**是不可接受的；动别人负责的代码前先在 §8 留一句

### 铁律 5：**改动走分支，审完再合并**

**并发改动是常态**，所以有风险或涉及面大的改动都留在分支上，等别的会话审完再进 `main`。

**分层关系（改动前必须理解，否则会改错层）：**

```
proto_link.c      帧收发（USB CDC）
      ↓
proto_frame.c     校验/打包/解包
      ↓
proto_app.c       协议状态机 + 插补器（只产生"角度"）
      ↓
arm_joint.c       按 kind 分叉：位置型直通 / 速度型闭环
      ↓                    ↓
arm_pwm.c            as5600.c / mpu6050.c
脉宽 ↔ CCR           I²C 传感器（角度 / 姿态）
```

**关键约定：`arm_pwm.c` 永远不知道 AS5600/MPU6050 存在。** 往 `arm_pwm.c` 里塞 I²C 调用 = 分层炸了。

### 6.5.2 换板踩到的坑：CubeMX 用有损编码重写了带中文注释的文件

**现象**：GENERATE CODE 之后 `main.c` / `usbd_cdc_if.c` 变成**非法 UTF-8**，编辑器读不了。

**根因**：CubeMX 重新生成这两个文件时用系统代码页（GBK）回写，把三字节汉字的
**最后一个字节写成了 `?`（0x3F）**。因为三字节变三字节，**文件大小一个字节都没变**，
所以 `git diff` 只看得到内容变化，看不出"编码坏了"。

**规模**：`main.c` **59 行 / 131 个字**，`usbd_cdc_if.c` **4 行**。`main.c` 里全是用户
手写的教学标注，不能 `git checkout` 了事。

**修法**（已做完，脚本用完即删）：拿 `git HEAD`（完好的 UTF-8）逐行比对，
**ASCII 骨架必须逐字节相同**、非 ASCII 字符允许"原样 或 被 1~3 个替换符顶掉"，
匹配上才把整行换回 HEAD 版本。这样 CubeMX 真实改过的代码行不会被误覆盖。

**下次 GENERATE CODE 会重演。** 判据一条就够：

```powershell
$p='Core\Src\main.c'; $b=[IO.File]::ReadAllBytes($p)
try { [void][Text.UTF8Encoding]::new($false,$true).GetString($b); "OK" } catch { "坏了：$($_.Exception.Message)" }
```

修 `.ld` 的同时顺手跑一遍这个检查。

**顺带发现**：`STM32F103C8Tx_FLASH.ld` **被 `.gitignore` 忽略**（`git status` 里从来
看不到它），所以那个"每次生成都要修 4 处"的毛病不会出现在提交记录里，也不用提交。

### 6.6 底座闭环：AS5600 到货后怎么接（**会话 A 负责**，2026-11-11 19:50 写）

底座 J1 是 **360° 连续舵机**（脉宽只决定速度，没有位置反馈），要靠 AS5600 磁编码器做闭环。
**代码已就绪，只等硬件。**

**已就绪的部分**

| 项 | 在哪 | 状态 |
|---|---|---|
| I²C 读取（0x36，12 位，`360/4096` °/LSB） | `as5600.c` | ✅ |
| **坐标系换算**（零位偏置 + 方向符号） | `arm_joint.c` → `base_read_deg()` | ✅ 两个宏待标定 |
| 闭环（前馈 + P + 死区 + 限幅） | `arm_joint.c` → `vel_tick()` | ✅ |
| 走线软限位 ±170° | `arm_cfg.c` 表里的 `deg_min/deg_max` | ⏳ 翻 kind 时填 |

**为什么必须要「坐标系换算」**：AS5600 输出的是 0~360° 的**原始**角，参考系是磁铁自己。
磁铁粘在哪，零点就在哪，跟你机械上的「底座零位」毫无关系。不换算的话，第一次接上就会看到
「手臂明明朝正前方，`q1_act` 却报 213.7°」。

**到货后按这个顺序做，一步都别跳**

1. **先确认磁铁**（详见 §9 待办）：必须是**径向充磁**（diametrically magnetized）。
   轴向充磁的普通圆片磁铁**装上去读数一动不动** —— AS5600 测的是穿过芯片表面的**磁场方向**，
   轴向磁铁转起来方向没变。
2. **台架试读**（先别装机械臂）：`VCC=3.3V`（⚠️ **不是 5V**）/ `GND` / `SCL=PB6` / `SDA=PB7`。
   手拿磁铁在芯片上方 1~2mm 慢慢转，看 `as5600_read_deg()` 是否 **0→360 均匀变化**。
   读数跳变或不动 = 磁铁不对 / 气隙不对 / 极性不对。
3. **机械安装**：磁铁粘在**转的那一侧**（底座转盘），板子固定在不动的一侧。
   气隙 **1~2mm**（0.5~3 可接受）；磁铁中心与芯片中心同轴偏差 **≤0.5mm**（偏了会产生周期性正弦误差，怎么标都标不准）。
4. **标定坐标系**（`arm_cfg.h` §五那两个宏，注释里有完整步骤）：
   - 步骤 0：`ARM_BASE_U_MAX_US` 临时改 `50.0f`
   - 步骤 1：底座转到 **home（手臂朝正前方 = 机械角 90° = 行程中点 CENTER）**，读 `as5600_read_deg()` → 填 `ARM_BASE_ENC_ZERO_DEG`（2026-11-12 `94335b1` 起语义就是"机械角 = CENTER 时的读数"，**不再有"机械零位到底是 0 还是 90"的歧义**）
   - 步骤 2：发 q1 = +5°，看实际转向 → 正方向填 `+1.0f`，反方向填 `-1.0f`
   - 步骤 3：`U_MAX_US` 调回 `300.0f`
5. **翻 kind**：`arm_cfg.c` 里 J1 改 `.kind = ARM_JOINT_VEL`、`.deg_min/-170`、`.deg_max/+170`、`.deg_home/0`、`.us_stop/1500`。
   ⚠️ **必须满足 `deg_home == (deg_min + deg_max) / 2`**：`94335b1` 的公式靠这个把 ZERO 锚在行程中点。
   现有四路本来就都满足（J1/J2/J3 `90=(0+180)/2`、J4 `30=(0+60)/2`），翻成 `-170/+170/0` 也满足（`0=(-170+170)/2`）。
   ⚠️ 但 ±170 行程只有 **340°**，接缝离两端各剩 **10°**（不再是 90°）—— 所以**限位判据必须真的能拦住**，
   冲出去 10° 就会绕到另一侧，误差瞬间变成 ±340°。宁可把 `deg_max` 收到 ±165 留 15° 余量。
6. **调 `us_per_dps`**：给固定脉宽偏置、测角速度 → 得到 µs 每 (°/s)。标出来才能开 `ARM_BASE_FF_ENABLE`。

**⚠️ 一条保命规矩**：`ARM_BASE_ENC_SIGN` 填反 = **正反馈**。误差越大推得越狠，
舵机会一路顶死在限位上烧掉，而 `status` 的 bit2 **不一定报**（在错误坐标系里误差一直在减小）。
所以步骤 0 的限幅**不能省**。

**共用总线提醒**：AS5600（`0x36`）和 MPU6050（`0x68`/`0x69`）共用 `PB6`/`PB7`，**地址不冲突**。
两块模块各自带 4.7k 上拉，并联后约 2.35k，仍在 I²C 允许范围，**不用额外加电阻**。
两边都必须是 **3.3V** —— 只要有一块接 5V，它的上拉就会把整条总线拉到 5V，另一块会被打死。

> 🚨 **状态位 bit4（`0x10`）≠ MPU6050 坏了（2026-11-15 19:55 会话 G 定位，别再往传感器上查）**
>
> **现象**：ArmHost 状态位常亮 `0x10`、右侧红字「传感器失效」、底部反复弹
> 「I²C 传感器失效 (bit4) — 按协议设备应已停止运动并置故障位」，

>
> **真相**：`PROTO_ST_I2C_FAIL`（bit4）有**两个来源**（`proto_app.c:186`）：
>
> `if ((s_i2c_fail != 0u) || (arm_joint_base_fault() != 0u)) { st |= PROTO_ST_I2C_FAIL; }`
>
> ① `s_i2c_fail` = MPU6050 丢线；② `arm_joint_base_fault()` = **AS5600 底座编码器读不到**。
> 而 J1 从 2026-11-13 起 `.kind = ARM_JOINT_VEL`（`arm_cfg.c:77`，为编码器闭环改的），
> 只要 `vel_tick()` 里 `base_read_deg()` 失败就置 `s_base_fault = 1`（`arm_joint.c:145-147`）。
> **AS5600 还没到货、没接线 ⇒ 这一位必然常亮**，和 MPU6050 一点关系都没有。
>
> **它不挡运动**：挡运动的是 `s_sensor_fault`（`move_start()` :416 / `on_debug_pulse()` :792）；
> `s_base_fault` 只影响 bit4 和 `arm_joint_moving()`（后者在故障时返回 0，`arm_joint.c:355`，
> 所以 bit3 也不会跟着误报）。**ArmHost 那句「应已停止运动」是上位机自己按 bit4 猜的，对底座编码器这一路不成立。**

#### 二、★★★ 最大的陷阱：**不要给 J2/J3/J4 套 PID**

1. **它们是模拟位置舵机，内部自带 PID**（厂家芯片里的位置环）。在外面再套一层位置 PID，
   等于**两级积分器串联**，极易振荡，而且物理上没有意义。
2. **外层 PID 的被控量根本不存在**。`arm_joint_get_deg()` 对 POS 关节返回的是
   `arm_get_deg()` —— **由 CCR 反算出来的指令角**（`arm_joint.c:242`），和指令同源。
   把指令当反馈，误差恒等于 0，PID 输出恒为 0：**看起来很完美，其实什么都没做**。
3. 答辩被问「你的 PID 怎么验证有效」，答「误差一直是 0」＝ 自己承认反馈是假的。
   被问「为什么不给肩肘加闭环」，正确答法：**模拟舵机的位置环在舵机里，不在这块 MCU 上；
   MCU 对它只负责"发对数"，不负责"控位置"**。

#### 三、J1 的闭环**代码已经写好了**，缺的只是硬件

`Core/Src/arm_joint.c:108` 的 `vel_tick()` 现成的控制律（**注意它现在不执行**）：

```c
err = wrap180(s_tgt_deg[joint] - meas);        /* ② 误差绕到 ±180 */
/* ③ 软限位：在端点且 err 朝外 → 直接停 */
u = u_ff + (ARM_BASE_KP_US_PER_DEG * err);     /* ④ 前馈 + 纯 P，:153 */
u = clamp(u, ±ARM_BASE_U_MAX_US);              /*    :155-156 */
if (|err| < ARM_BASE_DEADBAND_DEG) u = 0.0f;   /*    :159-162 死区，连前馈一起清 0 */
arm_set_us(joint, us_stop + u);                /* ⑤ 写脉宽 */
```

| 参数（`Core/Inc/arm_cfg.h`） | 现值 | 含义 |
|---|---|---|
| `ARM_BASE_KP_US_PER_DEG` | `3.0f` | 纯 P 增益，µs/° |
| `ARM_BASE_U_MAX_US` | `300.0f` | 输出限幅（±µs）；`us_stop=1500` 时可打到 1200~1800 |
| `ARM_BASE_DEADBAND_DEG` | `1.5f` | 死区，进死区输出清 0 |
| `ARM_BASE_FF_ENABLE` | `0` | 前馈**关闭**；打开需要 `us_per_dps`，**还没标定** |
| `ARM_BASE_ENC_ZERO_DEG` | `0.0f` | **待标定**，语义＝「机械角 = CENTER(=90°) 时的读数」 |
| `ARM_BASE_ENC_SIGN` | `+1.0f` | **待实测**，物理转向与角度增大的关系 |

**为什么它一行都不执行**：`arm_joint_tick()` 在 `arm_joint.c:258` 按 `kind` 派发，
只有 `ARM_JOINT_VEL` 才调 `vel_tick()`。而 `arm_cfg.c` 里**四个关节全是 `ARM_JOINT_POS`**。
翻成 VEL 需要**先有 AS5600**，标定步骤见 §9「底座 J1 / AS5600」和 `arm_cfg.h` §五。
⚠️ 翻之前务必复核 §7 那两条编码器炸点（`94335b1` 已修，但标定值还得实测填）。

#### 四、加 I / D 之前**必须先解决**的三件事（不做必炸）

1. **★ 死区和积分的死结**：`arm_joint.c:159` 的死区是**在限幅之后把 `u` 直接清 0**
   （连前馈一起清）。一旦加 I，积分项在死区内**照样累加**，但输出被清 0，
   等误差走出死区时积分已经攒了一大坨 → **阶跃式冲击 / 自激振荡**。
   → 正确做法：**在死区内清零积分**（或"误差在死区内就不累加"），别只在输出端清 u。
2. **积分饱和**：`U_MAX = 300 µs`。给积分项单独限幅（`I_MAX`）或做 anti-windup（回算法）。
   否则起步那几秒积分会一直涨到顶。
3. **D 项不能直接吃编码器**：AS5600 是 0.0879°/LSB，200 Hz 采样下差分出的"速度"抖动很大，
   **D 就是把噪声放大器**。必须配低通。这和 §8 里「锯齿 = 量化」是**同一个物理事实**，
   只是换了个地方冒出来。
